ISSUE 1: CONTACT FORM NOT WORKING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

ROOT CAUSE (confirmed by reading the code):
  - .env.local line 10: RESEND_API_KEY=   ← EMPTY, no value set
  - When RESEND_API_KEY is missing, the API route (src/app/api/contact/route.ts)
    returns HTTP 500 immediately (line 50-53).
  - The frontend (ContactPageClient.tsx line 41) throws when res.ok is false.
  - This means WhatsApp ALSO never opens — it is placed AFTER the API check
    (line 44-52 only runs on success).

WHAT NEEDS TO BE DONE:

  STEP 1 — Get a Resend API Key (USER ACTION REQUIRED)
  ─────────────────────────────────────────────────────
  1. Go to https://resend.com and create a free account.
  2. In the dashboard, click "API Keys" → "Create API Key".
  3. Copy the key (starts with "re_").
  4. Open .env.local and set:
       RESEND_API_KEY=re_XXXXXXXXXXXXXXXXXXXXXX
  5. To send FROM a professional address (not sandbox):
     - Go to Resend → Domains → Add Domain → add "alsaffar.pro"
     - Add the DNS records Resend gives you to your domain registrar.
     - Once verified, uncomment and set:
         CONTACT_FROM_EMAIL=Alsaffar Website <noreply@alsaffar.pro>
     NOTE: Until the domain is verified, email can ONLY be received
           by the same email you registered with at Resend (sandbox limit).

  STEP 2 — Code Fix: Make WhatsApp Always Deliver (Even If Email Fails)
  ─────────────────────────────────────────────────────────────────────
  FILE: src/app/[locale]/contact/ContactPageClient.tsx

  Current flow:
    POST to API → if success → open WhatsApp → show success
    POST to API → if fail   → show error (WhatsApp never opens)

  Fixed flow:
    POST to API → open WhatsApp regardless → show success
    If API fails → still show success + note that WhatsApp was opened
    (Email is secondary; WhatsApp delivery is guaranteed)

  CHANGE in handleSubmit():
    - Move the wa.me window.open() call BEFORE checking res.ok
    - OR: catch email failure separately and still open WhatsApp
    - Remove the hard throw on API failure; instead degrade gracefully

  STEP 3 — Code Fix: API Route Graceful Failure (optional but good)
  ─────────────────────────────────────────────────────────────────
  FILE: src/app/api/contact/route.ts

  Current: If RESEND_API_KEY is missing → returns 500 (form shows error)
  Fix:     If email fails, log the error but return { ok: true, emailFailed: true }
           so the frontend can still open WhatsApp without showing an error.

  DELIVERABLES:
  ✓ Form submits successfully
  ✓ Email arrives at support@alsaffar.pro (once API key is set)
  ✓ WhatsApp opens with pre-filled message (always, even if email fails)
  ✓ No error message shown to user

ISSUE 2: FREE CONSULTATION — TWO-PHASE AUTO-REPLY IN LIVE CHAT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FILE: src/components/shared/LiveChatBar.tsx

CURRENT STATE:
  - Single keyword-based getBotResponse() function
  - Default fallback: "Thank you for your message! To get detailed
    assistance… contact WhatsApp…"
  - No conversation state — every message is treated independently
  - No data collection, no phases

REQUIRED CHANGE: Stateful Two-Phase Conversation Flow

  PHASE 1 — Auto Greeting + Sequential Questions
  ───────────────────────────────────────────────
  When the chat opens, the bot immediately greets and then asks
  for information one question at a time:

  Step 0 (Welcome):
    "Welcome to Alsaffar! I'll help you get a free consultation.
     May I have your full name please?"

  Step 1 (after user replies with name):
    "Thank you, [name]! Which country are you from?"

  Step 2 (after user replies with country):
    "Great! Which service do you need?
     - Domestic Workers
     - Drivers
     - Skilled Workers
     - Corporate Staffing
     - Visa Processing"

  Step 3 (after user picks service):
    "Perfect. What is your phone number
     (with country code, e.g. +966XXXXXXXX)?"

  Step 4 (after user gives phone):
    "Any additional notes or special requirements?"

  PHASE 2 — Confirmation + Submit to WhatsApp
  ────────────────────────────────────────────
  Step 5 (after notes):
    Show summary:
    "Thank you! Here is your consultation request:
     ────────────────────
     Name:    [name]
     Country: [country]
     Service: [service]
     Phone:   [phone]
     Notes:   [notes]
     ────────────────────
     Sending your request now..."

    Then automatically open WhatsApp with all collected data as a
    pre-filled message to +966920021201.

    Final bot message:
    "Your request has been sent! Our team will contact you shortly
     on [phone]. You can also click here to follow up on WhatsApp."

  Arabic version of all the above should also be implemented (isAr).

IMPLEMENTATION PLAN:
  1. Add a chatStep state variable (0-5) and a collectedData object:
       { name, country, service, phone, notes }
  2. Remove getBotResponse() keyword matching (or keep as fallback
     for step 0 only, in case user types something unexpected).
  3. Each step: bot asks the question, user replies, data is stored,
     step advances.
  4. At step 5: format a WhatsApp message and call window.open().
  5. Support both EN and AR for all bot messages.

  STATE MACHINE:
    step 0 → ask name
    step 1 → save name, ask country
    step 2 → save country, ask service (show options)
    step 3 → save service, ask phone
    step 4 → save phone, ask notes
    step 5 → save notes, show summary, open WhatsApp, show confirmation
